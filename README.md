# Warhammer Ancient Battles 2.0 — data for New Recruit

BattleScribe-format data (`.gst` game system plus one `.cat` catalogue per army) for **Warhammer Ancient Battles 2nd Edition** and its supplements, for use in the [New Recruit](https://www.newrecruit.eu/) army builder.

**Version 0.1.0** (first release). This is an unofficial fan project. See [Disclaimer](#disclaimer).

## What is in here

| | |
|---|---|
| `Warhammer_Ancient_Battles_2.gst` | The game system: profile types (Model, Armour Save, Requirements, …), weapons, armour, shields and barding, special rules, categories, and the single neutral force entry |
| `*.cat` | One catalogue per army list, 246 in all, named `<Army>_<Book>.cat` |
| `issues/` | One text file per book: printed oddities, open questions and what would resolve each one (start with `issues/README.txt`) |
| `tools/` | The scripts that generate and post-process everything (see [How it is built](#how-it-is-built)) |
| `extraction_review.txt` | Historical: what the first pilot extractor detected for four AoA2 lists (those pilot catalogues were later removed in favour of the full AoA2 set) |

Game system revision: **20** (release v0.1.0). All catalogues reference it.

## Using it in New Recruit

1. Load the repository (or the `.gst` and the `.cat` files) as a custom game system. This data has not been exhaustively tested in New Recruit; if a catalogue fails to load, the error message is the most useful thing to report.
2. Create a roster and add a force. The game system has **one neutral force**, "Army"; the faction is the catalogue you pick.
3. Where an army has several wars, periods or sub-lists, choose it in the **Army composition** picker. Its percentage limits, which units are allowed, and unit costs and statistics all follow the choice.
4. Add units. New Recruit shows validation warnings for any rule that is broken.

## How the data behaves

**Army composition.** Percentages (Characters, Common, Uncommon, Cavalry, …) are enforced by points through modifiers on the force's categories, tested against the catalogue's composition picker. Units not listed for the chosen composition fail validation or are hidden.

**Armour Save and Sv.** Each model has an *Armour Save* profile built from its armour, shield and barding, and an **Sv** value in the stat line after Ld. Both update as options are ticked. Mounted models get the cavalry pip, buckler conditions and the 3+ / 2+ maximum from the rulebook. M is reduced for encumbrance (infantry with a 4+ or better save −1", cavalry with 3+ −1", metal barding another −1"); the printed M in the lists is unencumbered.

**Equipment options are all-or-nothing.** On troop units, options ("may have…", "replaces…") are unit-level checkboxes that apply to every model; the cost is the per-model cost times the number of models. Characters keep per-model options. Where a book explicitly lets a unit mix weapons, the unit has separate model entries instead: Polk and Smerd (Russian), Foot soldier (Carolingian) have "(spear)" and "(bow)" models, and bowmen may not outnumber spearmen.

**Command options.** Every troop unit has Leader, Standard bearer and Musician (+5 points each, once per unit; free for the Republican Roman manipular units; Roman Legionaries use a Centurion at +10).

**Crew and elephants.** Additional crew are folded into the crew entry: the entry's maximum is the base crew plus the extras, and the extra crewmen's points are charged on the unit, so the crew line reads "Crew (x3)" as you add them. On elephant units only the elephants count as models in the unit size; mahouts and crew are not counted.

**Requirements profile.** Any unit that depends on another unit has a *Requirements* line with three fields:
- *Take first*: what must already be in the army ("At least one of: Oscan Warriors", or per-war: "In First Punic War: at least one of: Mercenary Hoplites").
- *Limit*: ratios and point allowances ("1 per unit of Oscan Warriors", "1 per 500 points in the army (shared with Stone Thrower)").
- *Not with*: exclusive choices (alternative generals, mounted versus dismounted versions of a unit).

### Validation that is enforced

- **Unit ratios** ("one X per Y units of Z") are a minimum on the base unit: the base unit shows an error when you have fewer than the ratio needs, whatever order units are added in. Example: Carthaginian Skirmishers need at least one unit for every Balearic, Ligurian, Sardinian or Moorish skirmisher unit. Where several base units share a rule (the Ballista, Hypaspists per Pezhetairoi, Epigonoi or Experimental Phalanx, Chinese war machines per Halberdier or Spearman unit) the minimum sits on the first base unit and is reduced by one for each unit of the others, so any mix of them satisfies it. The only exception is "unless none" rules such as the Spanish Caetrati, which stay a maximum on the dependent unit.
- **Unit size and figure limits**, for example "may not be the largest unit of skirmishers" (Carthaginian and Roman slingers and archers), Slave Warriors against Illyrian Warriors, Tartars against Szekelers, Germanic Unfree against Warrior Elite, Numidian Trained Infantry against Warriors. These apply once the unit they are compared with is in the army. With several comparison units the total of their figures is used, which is lenient.
- **Per-war availability and "R:" restrictions** (Carthaginians, Republican Romans, Spanish sub-lists). A unit that needs another unit first can be added at any time; the error then appears on the prerequisite unit ("needs at least 1"), so it names what to add. Units not on the chosen war's list are hidden, and in lists with several wars or periods every unit stays hidden until you pick the Army composition, so the first step is obvious.
- **Either/or choices** (alternative generals, King or Marshal, Leves or Velites, mounted or dismounted versions): once one is in the army the other disappears from the add list and still fails validation if it was added first.
- **0-1 limits**, one General (alternative generals exclude each other), once-per-army options, per-composition costs and statistics.
- **Points-based limits** ("one per 500 or 1,000 points" for artillery, war wagons, elephants and scythed chariots), shared across the units that share the allowance. The roster total includes the unit being added, so these are slightly lenient.
- **Chariot squadrons** need at least three chariots.

### Not enforced (documented in the unit text or List Notes)

- "May not outnumber any other unit of cavalry" and similar comparisons against the largest or smallest of several units.
- Weapon mixes that cannot be expressed on unit-level checkboxes, such as "bows may not outnumber other weapons in the army".
- Allies from other lists, optional rules, and scenario or campaign content.
- Some Hannibal & the Punic Wars skirmisher rules (Spanish Balearic/Gallic) and a few deferred Armies of Antiquity v2 list fixes; see the `issues/` files.

Each book's specifics are in the `issues/` file for that book and in the *List Notes* rule of each catalogue.

## How it is built

Everything is generated; do not edit the `.cat` files by hand.

```
tools/<book>_data.py     the army lists as Python data (M(...) models, U(...) units, variants)
tools/<book>_build.py    writes the catalogues
tools/<book>_all.sh      build + the post-processing chain + lint
```

Books with a script: `ac` (Chivalry), `ad` (Alexander), `aoa` (Armies of Antiquity v1), `aoa2`, `aow` (Art of War), `arthur`, `bz` (Byzantium), `cw` (Chariot Wars), `el` (El Cid), `fw` (Fall of the West), `sp` (Spartacus), `sw` (Shieldwall), `vlad`. The rulebook lists use `rb_build.py` then `catalogue_tags.py` (adds the "(Main Rulebook)" tag to the catalogue names and drops a leading "The " from names so they sort properly); Hannibal uses `hb_build.py` and `hannibal_limits.py`. The base game system comes from `build_wab2.py` (it no longer writes the four pilot catalogues the full AoA2 set replaced).

Post-processing steps run, in order, by every `<book>_all.sh`:

| Script | Does |
|---|---|
| `add_unit_upgrades` | Leader, Standard bearer, Musician options |
| `replace_options_to_unit` | Equipment options become all-or-nothing unit checkboxes (command options flat cost) |
| `profile_swaps`, `equip_defs`, `mount_profiles`, `equip_save` | Weapon and armour definitions, Armour Save, encumbrance |
| `collapse_forces` | One neutral force plus composition pickers |
| `light_troops` | Links the Light Troops rule |
| `<book>_limits` | Per-book rules; uses `limlib.py` and `ratiolib.py` (ratios as minimums, figure caps) |
| `option_excl` | Mutually exclusive options (Light/Heavy armour, spear types, horse/warhorse) from `option_excl.json` |
| `figure_limits` | Total-figure rules for Alexander, Byzantium and Vlad |
| `prereq_min`, `excl_hide`, `compose_first` | Prerequisites as a minimum on the prerequisite unit; hide the excluded half of either/or choices; hide all units until the Army composition is picked |
| `req_notes` | The Requirements profile |
| `sv_stat` | Sv in the stat line |
| `crew_merge`, `elephant_count` | Crew line and elephant unit size |
| `mix_models` | Spear/bow model split (AoA2) |

Hannibal has no `_all.sh`; run `python3 tools/prereq_min.py .`, `python3 tools/excl_hide.py .`, `python3 tools/compose_first.py .`, `python3 tools/req_notes.py .` and `python3 tools/sv_stat.py .` on that folder after `hb_build.py` and `hannibal_limits.py`, then `python3 tools/roman_fixes.py .` (Raw Hastati upgrade, Balearic Slingers unavailable). `tools/composition_exclusions.py` hides units a composition bans (run by the aow, aoa2, bz and fw scripts); `tools/audit_compositions.py` is a read-only check of what each composition can field, and `issues/Composition_review.txt` lists the open questions.

The AoA2 lists come from the source PDF: `aoa24_extract.py`, then `aoa2_gen.py` → `aoa2_data.py`, with corrections in `aoa2_fixes.py`. Other one-off fixers are `fix_command_costs.py` and `fix_chariot_sizes.py` (for catalogues built before the fix; the builders now do it themselves).

Check any folder with `python3 tools/lint_wab2.py .` (well-formed XML, unique ids, every link resolves).

### Conventions

- Page references: Armies of Antiquity (1999), Chariot Wars and Hannibal book page = PDF page − 2; Byzantium, Vlad and Arthur PDFs = printed + 2; Shieldwall PDF = printed.
- IDs are deterministic (hashes of the names), so rebuilds produce stable ids.
- Values are used as printed. Where a printed value looks wrong it is entered as printed and listed in the matching `issues/` file.
